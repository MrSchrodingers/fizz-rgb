# ERR-20260521-1322 — Typing degradation (double-input / freezes) from 30fps HID stream flood

- **Date:** 2026-05-21
- **Severity:** High (degraded typing on the user's primary keyboard, system-wide perception)
- **Component:** `packages/daemon` — `EffectEngine` per-key streaming loop + `NodeHidController`
- **Introduced by:** the "games drop" (v0.3.0) — interactive games and reactive per-key effects (`perkey.startPattern`)

## Symptom

While a host-streamed per-key effect/game was active (a `spark` reactive trail in
the reported case), typing on the K617 felt broken: keystrokes appeared to register
twice / "delete twice", and the keyboard intermittently froze. The daemon log showed
a recurring cycle of `sendFeatureReport failed after retries — treating as disconnect`
followed by stream restart.

## Root Cause

Host-streamed per-key patterns/games render at **30fps** and the streaming loop in
`EffectEngine.startPattern` wrote a per-key HID **feature report on every tick,
unconditionally**:

```ts
this.hid.sendFeatureReport(frame).catch(() => this.stopStreamLoop());
```

`NodeHidController.sendFeatureReport` (node-hid) performs a **synchronous, blocking**
USB control transfer. Two compounding problems:

1. **No coalescing** — identical consecutive frames (a reactive effect sitting idle,
   a game that only steps every N ticks) were re-sent 30×/sec even though the
   keyboard was already displaying them.
2. **No backpressure on the interactive/game paths** — unlike the generic pattern
   path (which had a `pendingSend` flag), the game paths queued overlapping work.

Flooding the K617's feature-report endpoint at 30fps contends with the keyboard's own
matrix scanning / input reporting on the *same* USB device. The result on the keys the
user is typing on: input lag, **stuck/repeated keys** (perceived as "deletes twice"),
**stalls** ("freezes"), and periodic control-transfer failures that the daemon treats
as a disconnect → **USB re-enumeration**, during which held keys repeat and input is
briefly lost.

Note: `key-capture.ts` only **reads** evdev passively (no `EVIOCGRAB`, no uinput, no
re-injection), so it was ruled out early — a passive reader cannot make another
application receive a duplicated keystroke. The defect was on the **write** side.

### Evidence

- `journalctl --user -u fizzd` showed a repeating disconnect/reconnect cycle, always
  while an interactive stream was active.
- Empirical confirmation: issuing `perkey.stopPattern` (stopping the 30fps stream)
  immediately restored normal typing while the `spark` pattern was active.
- The daemon held exactly one passive evdev fd; no fd/stream leak.

## Resolution

Added `packages/daemon/src/frame-coalescer.ts` — a `FrameCoalescer` that approves a
frame only when it differs (by value) from the last approved frame, and routed **all**
streaming send sites through a single `EffectEngine.pushStreamFrame(frame)` helper that
applies:

- **Coalescing** — drop identical consecutive frames (the keyboard already shows them).
- **Backpressure** — skip a tick while a prior blocking write is still in flight.

The coalescer is reset at every stream (re)start (`startPattern`) and in
`stopStreamLoop`, so a reconnect-driven restore always re-sends the first frame even if
its bytes are unchanged (the keyboard may have lost state).

### Verification

- New unit tests: `packages/daemon/test/frame-coalescer.test.ts` (4).
- New integration test in `engine.test.ts`: a `binary-clock` stream (constant output
  within a wall second) collapses ~6 ticks/200ms to ≤2 sends. Failed before the fix
  ("expected 6 to be ≤ 2"), passes after.
- Full daemon suite: 83/83 passing. Existing reconnect-restore tests still pass
  (they exercise the coalescer reset).
- Live: with the rebuilt daemon, a 12s `spark` stream produced **0 disconnects** and
  **0 key-capture read errors** (vs. the prior storm); daemon CPU ~1%.

## Prevention

- **Every new streamed effect/game must send through `pushStreamFrame`** — never call
  `hid.sendFeatureReport` directly inside a render loop. This is the single seam where
  coalescing + backpressure live.
- Consider lowering the interactive stream tick rate (e.g. 15fps) for effects that
  don't need 30fps; coalescing already removes redundant writes but a lower base rate
  further reduces USB contention while typing.
- When building the remaining games from the backlog, treat the keyboard as a shared
  USB device: the LED stream competes with the user's keystrokes on the same endpoint.
